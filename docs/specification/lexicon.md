# The TEO Lexicon

> Precision in language enables precision in orchestration.

This document defines the stable terminology used by The Ever-Evolving Orchestration.

A term should be added only when it represents a distinct concept, cannot be expressed clearly using an existing term, and is likely to remain useful as implementations evolve.

## Capability

A measurable function that may be provided by one or more implementations.

Examples include code execution, multimodal interpretation, grounded research, long-context analysis, structured output, and low-latency inference.

## Constraint

A condition that limits or shapes an orchestration decision.

Examples include cost, latency, privacy, tool availability, jurisdiction, context size, reversibility, and execution time.

## Decision

The selection of an orchestration strategy based on observations, interpreted requirements, governing policy, and available implementations.

## Decision system

A system that observes context, interprets requirements, selects an execution strategy, evaluates the result, and improves future decisions.

## Evaluation

The process of measuring how well a decision and its execution satisfied the intended outcome.

Evaluation measures result quality. It is not the same as verification.

## Evidence

Information used to support or challenge a decision, policy, capability claim, or evaluation result.

Evidence may include reproducible tests, primary documentation, measured outcomes, observed failures, and clearly identified expert judgment.

## Execution

The act of carrying out the selected orchestration strategy through one or more implementations, agents, tools, services, or human participants.

## Implementation

A concrete realization of one or more capabilities.

An implementation may be a model, agent, tool, service, local system, hybrid system, or future form of computational intelligence.

## Interpretation

The process of converting observations into task requirements, capability requirements, constraints, risks, and decision criteria.

## Learn

The stage in which evaluation results, verification outcomes, failures, and operational evidence are used to improve future decisions, policies, registries, or evaluations.

## Normative

Content that defines requirements necessary for conformance with TEO.

## Informative

Content that explains, illustrates, or supports TEO without defining a conformance requirement.

## Observation

A fact or signal available before a decision is made.

Examples include task description, repository state, available tools, budget, risk indicators, prior results, and environmental constraints.

## Policy

A rule or set of rules that guides decisions without requiring a permanent implementation choice.

## Provider

An organization or system responsible for making an implementation available.

## Registry

A versioned collection of implementations, capabilities, providers, evaluations, and related metadata.

## Routing

The process of assigning work to an execution strategy based on interpreted requirements and policy.

## Specification

The normative definition of TEO, including its decision model, capability model, policy requirements, verification requirements, and conformance criteria.

## Steward

A person responsible for improving TEO while preserving its principles, scope, precision, and public character.

## TEO Proposal

A structured public proposal for a significant change to the TEO specification, governance, terminology, conformance model, or reference architecture.

The abbreviation TEOP may be used after the term is introduced.

## Verification

Independent confirmation that an execution satisfied its expected behavior, requirements, or constraints.

Verification confirms expected behavior. It is not the same as evaluation.
