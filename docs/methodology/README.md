# Methodology

Reusable methods for evaluating routing quality, cost, latency, reliability, reproducibility, evidence strength, specialist allocation, and operational controls.

`docs/methodology/` is for methods that remain useful across repeated work. Dated records of a staging exercise, refresh, audit, activation, or recalibration belong under [`docs/history/`](../history/).

## Available methods

- [`routing-validation.md`](routing-validation.md) defines representative route coverage, ownership, worker selection, risk controls, verification, independence, and dispatch trace checks.
- [`specialist-allocation.md`](specialist-allocation.md) defines how TEO selects a core team, worker binding, optional domain specialist, supporting teams, risk controls, and verification path.
- [`specialist-freshness.md`](specialist-freshness.md) defines how volatile specialist facts are kept current without turning durable role cards into static product or standards databases.
- [`provider-aware-fallbacks.md`](provider-aware-fallbacks.md) defines failure classification and provider-aware recovery principles.
- [`community-conversations.md`](community-conversations.md) defines the public discussion and stewardship method for community-facing work.
- [`main-branch-protection.md`](main-branch-protection.md) records the reproducible method used to protect repository changes through review and CI.
- [`regulated-specialist-evidence-pilot-2026-08-06.md`](regulated-specialist-evidence-pilot-2026-08-06.md) remains an active bounded pilot method despite its dated filename; its evidence and expansion gates are still operationally relevant.

Historical executions of these or related methods are indexed under [`docs/history/`](../history/).
