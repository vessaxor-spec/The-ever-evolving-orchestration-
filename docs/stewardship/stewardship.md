# Stewardship

TEO is maintained as a public, vendor-neutral orchestration project.

## Steward responsibilities

- Preserve the project scope and constitutional principles.
- Require evidence for material routing changes.
- Keep provider-specific claims dated and traceable.
- Separate stable orchestration principles from fast-changing model data.
- Reconcile current-state documentation and the canonical Progress Tracker after material merged changes so repository prose does not lag executable truth.
- Preserve historical release records, dated audits, validation reports, and accepted capsules rather than rewriting history to resemble current `main`.
- Treat architecture refactoring as incomplete until behavior/API compatibility, dependency direction, tests, repository layout, and canonical documentation are aligned.
- Prevent private, proprietary, or identifying information from entering the repository.
- Record significant changes clearly enough for future stewards to understand them.

## Decision standard

A proposed addition should improve orchestration quality, reduce meaningful risk, or make the framework easier to implement. Additions that only increase complexity should be deferred.

Internal maintainability changes must preserve product behavior unless a separate, explicitly reviewed behavior change is in scope. Current architecture-migration state belongs in the Progress Tracker and architecture documentation, not in a parallel source of truth.
