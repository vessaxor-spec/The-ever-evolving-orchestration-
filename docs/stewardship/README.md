# Stewardship

Human-readable governance and maintenance guidance for evolving TEO without weakening its architectural principles, authority boundaries, or evidence discipline.

## Current-state records

- [`progress-tracker.md`](progress-tracker.md) is the canonical operational snapshot for current release identity, roster counts, workstream status, completion estimates, validation state, and NOW/NEXT/LATER sequencing.
- [`roadmap.md`](roadmap.md) records directional project priorities and accepted future research without creating runtime or routing authority.

## Stewardship documents

- [`stewardship.md`](stewardship.md) defines steward responsibilities and the project decision standard.
- [`repository-layout.md`](repository-layout.md) defines repository information-architecture stewardship and migration discipline.
- [`community-human-verification.md`](community-human-verification.md) defines the community stewardship path for optional independent human-verification evidence.

## Authority boundary

Stewardship documentation records project state and direction. It does not override machine-readable policy, active routing configuration, schemas, release contracts, or executable reference behavior. Historical release records, dated audits, validation reports, and accepted capsules remain historical evidence and should not be rewritten merely to mirror current `main`.
