# TEO Registry

The registry separates current ecosystem evidence from TEO's stable responsibility architecture.

## Sections

- [`providers/`](providers/) documents provider access, official sources, and provider-level constraints.
- [`models/`](models/) documents current model identifiers, availability classes, provider claims, and TEO routing roles.
- [`capabilities/`](capabilities/) defines stable provider-neutral capabilities and the evidence required to demonstrate them.
- [`benchmarks/`](benchmarks/) records reproducible results, provider claims, limitations, and routing relevance.

## Evidence discipline

Registry entries must distinguish:

- TEO-observed results
- independent benchmark evidence
- provider-reported claims
- deployment-specific facts
- unverified assertions

The registry may evolve rapidly. Teams, workers, specialist authority, and verification requirements should remain stable unless evidence shows the architecture itself is inadequate.
